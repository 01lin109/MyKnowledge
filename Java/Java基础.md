# 1.HashMap
![[Pasted image 20260612175651.png]]

当两个不同的 Key（比如 "apple" 和 "banana"），经过哈希函数计算后，居然算出了**同一个数组索引**，这就是哈希冲突。

Java 8 解决哈希冲突采用了组合拳：**扰动函数 + 链表（尾插法） + 红黑树**。

### 第一道防线：用“扰动函数”尽量避免冲突

在算索引之前，Java 会先对 Key 的 `hashCode()` 进行一次扰动，源码极其一行：

Java

```
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

- **原理**：把哈希值的高 16 位和低 16 位进行异或（^）运算。
    
- **目的**：混合高低位的信息。因为很多时候数组长度很短，算索引时只有低几位生效。通过扰动，让高位信息也参与进来，大幅降低冲突概率。
    

### 第二道防线：链表存储（尾插法）

如果还是冲突了，就在该索引（桶）的位置长出一条单向链表，新来的节点挂在链表末尾（**尾插法**）。

> 💡 **对比 Java 7**：Java 7 用的是头插法，但在多线程并发扩容时会导致链表成环，引发死循环。Java 8 改用尾插法，彻底解决了扩容死循环的问题。

### 第三道防线：红黑树化（Treeify）

如果链表太长，查询复杂度会从 $O(1)$ 恶化成 $O(n)$。为此 Java 8 引入了**红黑树**。

当一个桶同时满足以下**两个硬性条件**时，链表就会自动扭转成一棵红黑树：

1. **链表长度达到阈值**：`binCount >= 8`（即链表长度达到 8）。
    
2. **数组总长度达到阈值**：`MIN_TREEIFY_CAPACITY = 64`（整个 Map 的数组长度至少是 64）。
    
    - _注意_：如果链表到了 8，但数组长度小于 64，`HashMap` 会优先选择**扩容数组**，而不是树化。
        

## 2. HashMap 的扩容机制（Resize）

为了保证性能，`HashMap` 不能等到数组被塞得满满当当才去扩容。它内部有一个极其重要的指标：**扩容阈值（Threshold）**。

$$\text{扩容阈值 (threshold)} = \text{当前容量 (capacity)} \times \text{加载因子 (loadFactor)}$$

- **默认容量**：16
    
- **默认加载因子**：0.75（这是一个在时间和空间成本上的完美折中）
    
- **计算**：$16 \times 0.75 = 12$。也就是说，当 Map 里的元素总数达到 12 个时，就会触发**扩容（Resize）**。
    

### 扩容分两步：

1. **容量翻倍**：创建一个两倍大小的新数组（比如从 16 变成 32）。
    
2. **数据迁移（Rehash）**：把旧数组里的所有数据，重新计算位置，搬运到新数组里。
    

## 3. Java 8 扩容里的天才设计：高低位链表（免重算 Hash）

在 Java 7 中，扩容是一件极其痛苦的事。每个节点搬家时，都需要重新调用一轮哈希函数算出新索引：`hash & (newCapacity - 1)`。

而 Java 8 引入了一个数学神迹：**因为扩容是 2 倍扩容，旧节点在新数组中的位置，要么在“原位置”，要么在“原位置 + 旧数组长度”。**

### 它是怎么做到的？

在数据搬家时，Java 8 只需要把旧链表拆分成两条全新的链表：

- **低位链表（loHead, loTail）**：准备留在原索引位置的节点。
    
- **高位链表（hiHead, hiTail）**：准备搬家到 `原索引 + oldCap` 位置的节点。
    

拆分的依据非常简单，只需要判断：`(e.hash & oldCap) == 0`

- 如果结果为 **0**：说明这个节点对应的二进制位没有发生变化，位置不变。
    
- 如果结果不为 **0**：说明多出来一个 1，位置直接变成 `原位置 + oldCap`。
    

### 源码核心逻辑：

Java

```
Node<K,V> loHead = null, loTail = null; // 低位链表
Node<K,V> hiHead = null, hiTail = null; // 高位链表
Node<K,V> next;
do {
    next = e.next;
    // ⭐ 核心数学判断：直接看 hash 与旧数组长度按位与的结果
    if ((e.hash & oldCap) == 0) {
        if (loTail == null) loHead = e;
        else loTail.next = e;
        loTail = e; // 尾插
    } else {
        if (hiTail == null) hiHead = e;
        else hiTail.next = e;
        hiTail = e; // 尾插
    }
} while ((e = next) != null);

// 分好队后，整体搬迁，不需要重新计算具体索引，性能拉满
if (loTail != null) {
    loTail.next = null;
    newTab[j] = loHead; // 留在原位
}
if (hiTail != null) {
    hiTail.next = null;
    newTab[j + oldCap] = hiHead; // 搬到老位置 + oldCap
}
```

### 这一设计的巨大优势：

1. **性能极高**：完全不需要像 Java 7 那样重新对每个 Key 做复杂的取模和扰动计算，只需要简单的**位运算**判断是 0 还是 1。
    
2. **保持顺序**：因为用的是高低位双链表尾插，搬家过去后，节点的相对顺序完全没有变，极其优雅。
    

## 总结面试必背口诀

1. **哈希冲突怎么解？** 高低 16 位异或扰动，冲突了尾插成链表，链表长度过 8 且数组过 64 变红黑树。
    
2. **什么时候会扩容？** 元素总量超过 `容量 * 0.75` 触发扩容，每次扩容大小翻倍。
    
3. **Java 8 扩容强在哪？** 引入高低位链表，通过 `e.hash & oldCap` 分流，要么原地不动，要么挪动 `oldCap` 的距离，免去了重新计算 Hash 的性能开销。
