# 1.📝 知识库专栏：特定三元组计数问题

### 📌 题目描述

给定一个长度为 $n$ 的整数数组 `nums`（$-10^9 \le nums[i] \le 10^9$），寻找满足以下条件的三元组 $(i, j, k)$ 的数量：

1. **位置关系**：$0 \le i < j < k < n$
    
2. **数值等式**：$(nums[i] - nums[j]) \times 2 = nums[k]$
    

- **数据规模**：$t \le 10, \; n \le 5000$
    
- **返回值**：结果对 $10^9+7$ 取模。
    

### 💡 核心算法思路：定中点，控两端

- **破局关键**：直接三重循环复杂度为 $O(n^3)$ 必定超时。因为 $n \le 5000$，我们需要一个 **$O(n^2)$** 的解法。
    
- **核心技巧**：移项变形得 $nums[k] = (nums[i] - nums[j]) \times 2$。我们选择**固定中间的 $j$**，将 $i$ 和 $k$ 完全隔离在 $j$ 的左右两侧。
    
- **数据结构**：
    
    - `leftMap`：动态维护当前 $j$ **左侧**（即历史 $i$）每个数字出现的频次。
        
    - `rightMap`：动态维护当前 $j$ **右侧**（即未来 $k$）每个数字出现的频次。
        
- **状态转移（指针滑动）**：当 $j$ 向右移动一位时，过去的 $j$ 自动加入 `leftMap`，而新的 $j$ 从 `rightMap` 中移除。通过“**左侧补票，右侧退票**”实现动态平衡，避免重复建表。
    

### 🛠️ 生产级 Java 实现代码

Java

```
import java.io.*;
import java.util.*;

public class Main {
    private static final int MOD = 1000000007;

    public static void main(String[] args) throws IOException {
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        int T = Integer.parseInt(br.readLine().trim());
        StringBuilder sb = new StringBuilder();
        
        while (T-- > 0) {
            String line = br.readLine();
            while (line != null && line.trim().isEmpty()) line = br.readLine();
            if (line == null) break;
            
            int n = Integer.parseInt(line.trim());
            long[] nums = new long[n];
            if (n > 0) {
                StringTokenizer st = new StringTokenizer(br.readLine());
                for (int i = 0; i < n; i++) nums[i] = Long.parseLong(st.nextToken());
            }
            if (n < 3) { sb.append(0).append("\n"); continue; }

            // 1. 初始化：预将所有元素（除第一个外）放入右侧集
            Map<Long, Integer> rightMap = new HashMap<>();
            for (int i = 1; i < n; i++) rightMap.put(nums[i], rightMap.getOrDefault(nums[i], 0) + 1);

            // 2. 隔离带初始化：j=1 准备就位，左侧纳入 nums[0]，右侧剔除 nums[1]
            Map<Long, Integer> leftMap = new HashMap<>();
            leftMap.put(nums[0], 1);
            rightMap.put(nums[1], rightMap.get(nums[1]) - 1);

            long totalTriplets = 0;

            // 3. 线性扫描中间点 j
            for (int j = 1; j < n - 1; j++) {
                long currentJVal = nums[j];

                // 优化：只遍历左侧已去重的特征值，利用哈希表进行组合计数
                for (Map.Entry<Long, Integer> entry : leftMap.entrySet()) {
                    long iVal = entry.getKey();
                    long targetKVal = (iVal - currentJVal) * 2; // 防溢出公式

                    int kCount = rightMap.getOrDefault(targetKVal, 0);
                    if (kCount > 0) {
                        totalTriplets = (totalTriplets + (long) entry.getValue() * kCount) % MOD;
                    }
                }

                // 4. 状态滚动转移
                leftMap.put(currentJVal, leftMap.getOrDefault(currentJVal, 0) + 1);
                long nextJVal = nums[j + 1];
                rightMap.put(nextJVal, rightMap.get(nextJVal) - 1);
            }
            sb.append(totalTriplets).append("\n");
        }
        System.out.print(sb.toString());
    }
}
```

### ⚠️ 避坑指南（复盘防错）

1. **防止整型溢出**：题目中数值可达 $\pm10^9$，两数相减再乘以 2 必定打破 `int` 范围。代码中统一强制升级为 **`long`** 进行矩阵与哈希表 Key 运算。
    
2. **去重提速**：内层没有直接双重遍历数组，而是去迭代 `leftMap.entrySet()`。由于大厂测试数据中通常包含大量重复元素，去重后迭代能让实际执行时间大打折扣。
    
3. **空间换时间**：巧妙利用“两表滑动维护”将时间复杂度从 $O(n^3)$ 彻底降维至标准的 **$O(n^2)$**，空间复杂度仅为稳定 $O(n)$。


# 2.📝 知识库专栏：去绝对值转化为前缀最值问题

### 📌 题目描述

给定一个长度为 $n$ 的数组 $A$（$1 \le A_i \le 10^9$），定义任意两个元素对儿 $(i, j)$ 的 FST 距离为：

$$dist(i,j) = |i^2 - j^2| + |A_i^2 - A_j^2|$$

求整个数组中所有元素对儿中的**最大 FST 距离**。

- **数据规模**：$n \le 10^5$
    
- **核心难点**：直接双重循环为 $O(n^2)$ 必定超时。必须利用数学性质将时间复杂度降到 **$O(n)$**。
    

### 💡 核心算法思路：去绝对值与状态分离

由于最大距离与 $i$ 和 $j$ 的先后顺序无关，我们不妨直接规定 **$i < j$**。

1. **消去第一项绝对值**：因为 $i < j$，所以 $i^2 < j^2$，第一项直接去绝对值变成：$j^2 - i^2$。
    
2. **拆分第二项绝对值**：根据 $A_i^2$ 和 $A_j^2$ 的大小关系，拆分成两种情况，并**将 $i$ 和 $j$ 的项完全分离开**：
    
    - **情况 1 ($A_i^2 \ge A_j^2$)**：
        
        $$dist = (j^2 - i^2) + (A_i^2 - A_j^2) = \mathbf{(j^2 - A_j^2)} + \mathbf{(A_i^2 - i^2)}$$
        
    - **情况 2 ($A_i^2 < A_j^2$)**：
        
        $$dist = (j^2 - i^2) + (A_j^2 - A_i^2) = \mathbf{(j^2 + A_j^2)} - \mathbf{(i^2 + A_i^2)}$$
        
3. **动态规划/动态维护最值**：
    
    当我们从左到右遍历 $j$ 时，要让距离最大，只需要在 $j$ 之前（即历史已遍历过的 $i$ 中）找到：
    
    - 情况 1：最大的 $(A_i^2 - i^2)$
        
    - 情况 2：最小的 $(i^2 + A_i^2)$
        
    
    我们无需开辟完整的 DP 数组，只需要用两个变量滚动维护这两个前缀最值即可，成功将复杂度降至 $O(n)$。
    

### 🛠️ 生产级 Java 实现代码

Java

```java
import java.io.BufferedReader;
import java.io.InputStreamReader;
import java.io.IOException;
import java.util.StringTokenizer;

public class Main {
    public static void main(String[] args) throws IOException {
        // 使用 BufferedReader 加快输入速度，防止输入成为瓶颈
        BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
        
        String line = br.readLine();
        if (line == null || line.trim().isEmpty()) return;
        int n = Integer.parseInt(line.trim());
        
        long[] a = new long[n + 1]; // 采用 1-based 索引
        StringTokenizer st = new StringTokenizer(br.readLine());
        for (int i = 1; i <= n; i++) {
            a[i] = Long.parseLong(st.nextToken());
        }

        long maxDist = 0;

        // 初始化边界：将第一个元素作为初始的 i 归档到历史最值中
        // maxPart1 对应情况 1：维护前面最大的 (A_i^2 - i^2)
        // minPart2 对应情况 2：维护前面最小的 (i^2 + A_i^2)
        long maxPart1 = (a[1] * a[1]) - (1L * 1);
        long minPart2 = (1L * 1) + (a[1] * a[1]);

        // 从第 2 个元素开始遍历作为当前的 j
        for (int j = 2; j <= n; j++) {
            long jsq = (long) j * j;
            long ajsq = a[j] * a[j];

            // 1. 对应情况 1 拆解公式：(j^2 - A_j^2) + 历史最大的 (A_i^2 - i^2)
            long dist1 = (jsq - ajsq) + maxPart1;
            
            // 2. 对应情况 2 拆解公式：(j^2 + A_j^2) - 历史最小的 (i^2 + A_i^2)
            long dist2 = (jsq + ajsq) - minPart2;

            // 3. 更新全局最大距离
            maxDist = Math.max(maxDist, Math.max(dist1, dist2));

            // 4. 状态滚动更新：将当前的 j 作为新的历史档案，去竞争最值
            maxPart1 = Math.max(maxPart1, ajsq - jsq);
            minPart2 = Math.min(minPart2, jsq + ajsq);
        }

        System.out.println(maxDist);
    }
}
```

### ⚠️ 避坑指南（复盘防错）

1. **彻底解决整型溢出**：特征值 $A_i \le 10^9$，其平方最大可达 $10^{18}$，远超 `int` 的 21 亿限制。代码中不仅数组类型采用了 **`long[]`**，在计算索引平方时也使用了 `1L * 1` 或强转 `(long) j * j` 来实施自动类型提权。
    
2. **拒绝绝对值嵌套**：本题不超时的唯一方法就是利用数学变形**把 $i$ 和 $j$ 从绝对值里松绑**。只要能将它们划分到加号或减号的两端，就可以用类似动态规划前缀最值的思想把双重循环降成单层循环。

# 贪心降低讨论维度：
## 📌 题目一：双维度区间重叠（LeetCode 406. 根据身高重建队列）

### 1. 题目描述

假设有一群人站成一个队列，每个人用一对整数 `[h, k]` 表示，其中 `h` 是这个人的身高，`k` 是排在这个人前面且身高**大于或等于** `h` 的人数。让你重新排列这个队列，使其满足所有人的 `[h, k]` 条件。

> **示例输入：** `[[7,0], [4,4], [7,1], [5,0], [6,1], [5,2]]`

### 2. 为什么容易顾此失彼？

这里有两个互相影响的维度：身高 `h` 和前面高人的数量 `k`。

- 如果你先照顾 `k`（人数），换了位置之后，身高 `h` 变了，会直接破坏别人的 `k` 条件。
    
- 如果你先照顾 `h`，后面插入矮个子时，又可能乱了高个子的 `k`。两边一揉和，思路直接打结。
    

### 3. 如何砍掉一个思考维度？

**核心破题思路：按身高 `h` 从大到小排序。如果身高相同，按 `k` 从小到大排序。**

**为什么这样能降维？**

1. **废掉身高维度的后效性**：当我们按照身高从大到小依次把人插入到新队列时，**有一个天然的保障**——当前准备插入的人，绝对是目前所有已插入人里面“最矮的”（或并列最矮）。
    
2. **让 `k` 获得绝对自由**：既然他是最矮的，那么他被插在任何位置，**对那些已经躺在队列里的大佬们（比他高的人）完全没有任何影响**！大佬们低头看他，根本不计入自己的 `k`。
    
3. 此时，这个矮个子的 `k` 是多少，我们就大摇大摆地把他直接插入到新队列的第 `k` 个索引位置（Java 中 `list.add(k, person)`）。他前面就刚好有 `k` 个比他高的人。
    

通过身高降序，我们直接**废掉了“后插入的人会破坏先插入人的环境”这一维度**，把二维冲突降到了一维插入。

## 📌 题目二：双重资源竞争（LeetCode 1353. 最多可以参加的会议数目）

### 1. 题目描述

给你一个数组 `events`，其中 `events[i] = [startDay_i, endDay_i]`，表示会议 `i` 的开始时间和结束时间。你一天最多只能参加一个会议，而且只能在 `[startDay_i, endDay_i]` 期间参加。求你最多能参加多少个会议。

### 2. 为什么容易顾此失彼？

- 冲动贪心一：谁先开始我先参加谁（按 `startDay` 排序）。坑：一个会议今天开始，持续 100 天；另一个会议今天开始，只持续 1 天。你选了前一个，后一个直接废了。
    
- 冲动贪心二：谁时间短我先参加谁（按持续时间排序）。坑：时间短的可能在很靠后的日子才开始。
    

### 3. 如何砍掉一个思考维度？

**核心破题思路：时间轴往前推进，在所有“今天已经开始”的会议里，只挑“结束时间（`endDay`）最早”的会议。**

**为什么这样能降维？**

我们把时间拆成一个一维的指针 `day`，从第 1 天往后走：

1. **锁定开始时间**：把所有 `startDay == day` 的会议全部塞进一个**最小堆（优先队列）**里。堆的排序规则是：**`endDay` 越小，优先级越高**。
    
2. **释放结束时间的焦虑**：既然这些会议在今天都能参加，那么对于今天来说，哪个会议最紧急？当然是快要结束（`endDay` 最小）的那个！至于那些结束时间很晚的会议，今天不急着宠幸它们，后面大把日子可以选。
    
3. 如果堆顶的会议已经过期了（`endDay < day`），直接抛弃。否则，今天就参加堆顶的会议，并把指针 `day++` 推进到明天。
    

通过“时间流推进 + 最小堆”，我们成功把“在全局无数交织的区间里做选择”的恶心大局观，降维成了“**只看当下，谁最急谁上**”的每日打卡任务。

## 📌 题目三：双人组能力博弈（Codeforces 经典 / 大厂笔试常客：贪心分配）

### 1. 题目描述

有 $n$ 个任务，每个任务有两个属性：难度 $A_i$ 和回报 $B_i$。你有 $m$ 个员工，每个员工有能力值 $C_j$。一个员工只能完成难度 $A_i \le C_j$ 的任务，且每个员工只能接一个任务。如何分配才能让总回报 $\sum B_i$ 最大？

### 2. 为什么容易顾此失彼？

- 如果你派能力最强的员工去接回报最高的任务。坑：这个最高回报的任务可能极其简单（$A_i$ 很小），大材小用，导致后面来了一个巨难且回报也很高的任务，没人能做了。
    
- 如果你让员工去接他恰好能勉强应付的任务。坑：回报可能非常低，浪费了人手。
    

### 3. 如何砍掉一个思考维度？

**核心破题思路：员工按能力 $C_j$ 从小到大排序；任务按难度 $A_i$ 从小到大排序。**

**为什么这样能降维？**

我们让员工从小到大排好队，一个一个来挑任务：

1. **卡死难度限制（废掉 $A$ 维度）**：当能力最弱的员工 $j$ 走上来时，我们把所有难度 $A_i \le C_j$ 的任务全部丢进一个**最大堆（按回报 $B_i$ 从大到小排序）**。
    
2. **此时谁是自由的？**：由于我们后面走上来的员工能力 $C_{j+1}$ **一定比当前员工更强**，这意味着**当前这个弱员工能做的所有任务，后面的强员工百分之百都能做**！
    
3. **彻底贪心（释放 $B$ 维度）**：既然弱员工现在能做的任务，放进池子里后，后面更强的人也能做，那我们现在就不需要为后人留后路。当前员工直接从池子里**把回报 $B_i$ 最高（堆顶）的任务挑走**。
    

这就是通过排序“**让弱者先挑，把弱者能做的资源最大化，然后强吃最大利益**”的降维策略。

## 💡 总结：怎么在以后的题目中一眼看出这种“降维”机会？

当你读完一道题，发现它有两个限制维度（比如 $X$ 和 $Y$）相互牵绊时，在草稿纸上逼问自己这两个问题：

1. **“如果我强行对 $X$ 进行单向排序（从大到小或从小到大），能帮我锁死或者顺应某种趋势吗？”**
    
2. **“在 $X$ 已经有序的前提下，我能不能把对 $Y$ 的选择，变成一个‘无后效性’（即我现在的选择不会让后面的路变窄）的局部贪心？”**
    

如果答案是肯定的，立刻上“排序 + 结构体/二维数组”**或者**“排序 + 堆（PriorityQueue）”。这就跟你刚刚做的那道题一模一样：用 $A$ 的排序夺回掌控权，然后把自由留给 $B$。

# 📝 算法题本：网络游戏最佳跳关策略

## 1. 📋 题目描述

### 🎨 场景设定

小红在玩一个闯关游戏，游戏一共有 $n$ 个关卡。通过第 $i$ 个关卡需要消耗 $a_i$ 个单位时间。为了通关，小红必须**严格按照从前往后**的顺序通过每一个关卡。

### 🎁 奖励机制（充能）

每**通过** $k$ 个关卡，小红就会获得一个“跳关道具”。

- **跳关道具的属性：** 可以在**任意一个关卡**使用。使用后，可以直接不消耗时间（耗时变成 0）通过该关卡。
    
- **物理约束：** 跳关道具是在某一关通过后（打完后）才发放的。你不能使用尚未获得的道具。
    

### 🎯 求解目标

请问小红通过这 $n$ 个关卡，最少需要消耗多少时间？

### 📥 输入描述

- 第一行输入两个整数 $n, k \ (1 \le n, k \le 10^5)$，分别代表关卡数量和获得跳关道具的充能条件。
    
- 第二行输入 $n$ 个整数 $a_1, a_2, \dots, a_n \ (1 \le a_i \le 10^5)$，代表通过每个关卡原本需要消耗的时间。
    

### 📤 输出描述

- 在一行上输出一个整数，表示小红通过这 $n$ 个关卡所需的最少时间。
    

## 2. 💡 破题思路与“降维”设计

这道题表面上看是一个带有“动态充能”和“时序消费”的复杂问题。如果你试图去实时维护“小红手里当前有几张道具卡”，时序就会彻底错乱。我们需要通过以下两步进行**思维降维**：

### 🔑 降维突破口：看穿道具上限的“因果律”

因为小红必须打完所有关卡，所以无论道具怎么用，**通关的先后顺序是死死卡住的**。

当小红站在第 $i$ 关的门口时（数组下标为 $i$），她前面已经**完整通过了 $i$ 个关卡**。

根据每过 $k$ 关送 1 个道具的规则，此时她历史上能够获得的道具总上限，雷打不动就是：

$$\text{currentProps} = \lfloor \frac{i}{k} \rfloor$$

- **当 $i < k$ 时：** `i / k = 0`。意味着在前 $k$ 关，小红手里绝不可能有道具，必须实打实花时间硬啃。
    
- **当 $i = k$ 时：** `i / k = 1`。小红手里终于攒出了人生第一个合法道具，从这一关开始，她拥有了“免单申请权”。
    

通过 `i / k`，我们把**动态变化的道具卡数量，降维成了基于当前位置的静态上限限制**，彻底消除了后效性。

## 3. 🎯 核心策略：看大门式的小顶堆（Min-Heap）

我们希望用道具跳过**耗时最长**的关卡。但由于我们是单向往前走的，后面的关卡有多大我们事先不知道。这就是“反悔贪心”的用武之地。

我们用一个小顶堆（`PriorityQueue`）来当做我们的“免单白名单”。堆的体积代表占用的道具数，**堆顶（`minHeap.peek()`）永远是当前免单名单里耗时最短的“倒数第一名”**。

随着时间轴 `i` 从 $0$ 走到 $n-1$，我们全额累加总时间，并根据以下两个贪心策略动态调整堆：

### 策略 A：名额扩容（新道具解锁）

当 `i / k > minHeap.size()` 时，说明随着关卡推进，小红手里解锁了新的道具额度。既然免单白名单有了空位，我们不需要任何挑剔，直接把当前这一关的耗时塞进堆里。

### 策略 B：实力淘汰（反悔置换）

如果当前没有解锁新名额，说明免单位置满了。但如果新进来的关卡耗时非常恐怖（`times[i] > minHeap.peek()`），小红就会**反悔**：

Java

```
minHeap.poll(); // 把免单名单里最弱的那个踢出去（让它去老实花时间打）
minHeap.add(times[i]); // 把当前这个耗时巨大的新大佬塞进堆里免单
```

**这一进一出，在不增加道具消耗的前提下，精准淘汰了性价比最低的免单关卡，实现了全局最优。**

## 4. 🛠️ 100% AC 完美实现代码

该代码在空间上进行了极致优化，堆的体积永远不超过 $\lfloor n/k \rfloor$，空间复杂度 $O(n/k)$，时间复杂度 $O(n \log \frac{n}{k})$。

Java

```
import java.util.*;

public class Main {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int n = scanner.nextInt();
        int k = scanner.nextInt();

        int[] times = new int[n];
        for (int i = 0; i < n; i++) {
            times[i] = scanner.nextInt();
        }

        // 1. 计算整局游戏总共能获得的跳关道具终极数量
        int props = n / k;

        // 边界处理：如果没有道具，直接返回所有关卡时间总和
        if (props == 0) {
            long sum = 0;
            for (int time : times) {
                sum += time;
            }
            System.out.println(sum);
            return;
        }

        // 2. 初始化小顶堆，用来保存当前最值得用道具跳过（时间最大）的关卡
        PriorityQueue<Integer> minHeap = new PriorityQueue<>();
        long totalSum = 0;

        // 3. 流式单向遍历关卡
        for (int i = 0; i < n; i++) {
            totalSum += times[i]; // 先全额缴费

            // 核心神来之笔：利用下标 i 计算当前这一关开始前，历史上真正结余可用的道具数
            int currentProps = i / k;

            // 策略 A：如果当前已获得的道具数量多于堆的大小，说明刚获得了新道具，直接免单入堆
            if (currentProps > minHeap.size()) {
                minHeap.add(times[i]);
            }
            // 策略 B：名额爆满，但当前关卡时间比免单里最小的还要大，剔除弱鸡，置换大佬
            else if (currentProps > 0 && times[i] > minHeap.peek()) {
                minHeap.poll(); // 踢出免单名单中耗时最短的关卡
                minHeap.add(times[i]); // 将当前大耗时关卡加入免单
            }
        }

        // 4. 终局结算：从总耗时中，扣除所有留在小顶堆里的免单大头
        long skipSum = 0;
        while (!minHeap.isEmpty()) {
            skipSum += minHeap.poll();
        }

        System.out.println(totalSum - skipSum);
    }
}
```

# 贪心

## 1. 反悔贪心（Regret Greedy / Retrospective Greedy）

这个流派你已经非常熟悉了，它也是 PDD **最常考的压轴题型**。

- **核心思想：** **“先占住名额，后面遇到更好的再反悔置换”**。单向推进时间轴（或流式处理输入），不管三七二十一先贪心地做出当前最优选择（比如直接免单、直接选最贵的）。当后面遇到更优的资源且名额爆满时，通过优先队列（堆）瞬间抓出历史选择里最差的一个，将其淘汰并“反悔”踢出，换取当前更大的收益。
    
- **PDD 电商映射：** 裂变活动中“每天签到送代金券，但代金券有过期时间和持有上限，求最大羊毛收益”。
    
- **经典模板：** LeetCode 630. 课程表 III、你刚刚 AC 的“网络游戏最佳跳关策略”。
    

## 2. 区间贪心（Interval Greedy）

这是最考验**降维思考**和**排序策略**的经典流派，通常涉及一维时空轴上的区间重叠和重组。

- **核心思想：** **“通过特定维度的排序，彻底消除后效性”**。把错综复杂的区间段问题，通过按“左端点（开始时间）”、“右端点（结束时间）”或“区间长度”进行单向排序，转化为一维流水线作业。
    
- **三大经典子类型：**
    
    1. **区间选点问题：** 给定 $N$ 个闭区间，求最少需要多少个点，才能让每个区间都至少包含一个点。（_贪心策略：按右端点升序排列，每次把点选在区间的右端点。_）
        
    2. **不相交区间问题（活动安排）：** 给定 $N$ 个区间，求最多能挑出多少个互不重叠的区间。（_贪心策略：按结束时间升序排列，哪个先结束我先选谁。_）
        
    3. **区间覆盖问题：** 用最少的区间去完整覆盖一段指定的长区间。
        
- **PDD 笔试高频：** LeetCode 435. 无重叠区间、LeetCode 452. 用最少数量的箭引爆气球。
    

## 3. 交换贪心 / 排序贪心（Exchange Arguments）

当你面对一堆元素，不知道该按什么顺序去处理它们才能让收益最大或成本最低时，就要用**交换贪心（邻项交换法）**。

- **核心思想：** **“通过数学推导，自定义排序规则”**。假设现在有相邻的两个元素 $X$ 和 $Y$，我们去推导：如果把 $X$ 排在 $Y$ 前面，总代价是多少；如果把 $Y$ 排在 $X$ 前面，总代价是多少。通过建立代数不等式，消去共同项，最终推导出一个固定的**自定义比较器（`Comparator`）**。直接对原数组用这个规则执行 `Arrays.sort()`，排完序的顺序就是最优解。
    
- **PDD 电商映射：** “有 $N$ 个拼单订单需要合并打包发货。每个订单有紧急程度 $A_i$ 和等待时间成本 $B_i$，求一个最优的发货顺序，使总损失最小。”
    
- **经典模板：** 洛谷 P1080 [NOIP2012 提高组] 国王游戏、LeetCode 179. 最大数（拼接字符串让数字最大）。
    

## 4. 拓扑贪心 / 依赖贪心

当元素之间存在**先后依赖关系**（比如必须要先做完 A 才能做 B），同时又要求某种资源最大化时使用。

- **核心思想：** **“拓扑排序 + 优先队列”**。不能直接盲目对全局元素进行排序，而是结合图论的入度概念。每次只把当前所有入度为 0（即没有任何前置限制、现在立刻能做）的元素丢进优先队列（堆）中。然后在这个“自由候选池”里进行贪心挑选（挑收益最高的或耗时最短的）。每做完一个，更新它下游元素的入度。
    
- **PDD 后端映射：** “电商微服务系统的启动依赖拓扑。某些服务有高并发流量负载，在有服务器资源限制的情况下，求一个最优的系统启动/调度顺序”。
    
- **经典模板：** LeetCode 502. IPO（结合了项目启动资金限制的拓扑流贪心）。
    

## 5. 流式双指针贪心（Two-Pointer / Sliding Window Greedy）

这种类型通常不需要复杂的堆结构，而是利用两个数组的**双向单调性**进行极限拉扯。

- **核心思想：** **“田忌赛马，弱者先看”**。将两个相关的数组分别排序，然后用两个指针分别指向两个数组的开头（或两端）。让弱者先挑，如果当前最弱的资源能被满足，就直接分配；如果最弱的资源连当前最低的门槛都跨不过去，说明这个门槛极其恶劣，必须用最顶级的资源去砸，或者直接放弃。
    
- **PDD 电商映射：** “有 $M$ 个买家提出的秒杀出价，和 $N$ 件库存商品。每个商品有最低限价，每个买家有最高预算，求最大的撮合交易笔数”。
    
- **经典模板：** LeetCode 455. 分发饼干、LeetCode 881. 救生艇。
