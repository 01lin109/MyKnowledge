## 一、 BitMap 的工作原理

BitMap 的本质是一个**连续的二进制位数组（Bit Array）**。它抛弃了传统用独立变量（如 Int、Long）存数字的做法，而是**利用“数组的下标”来表示数字本身，用“该位的值（0或1）”来表示该数字是否存在**。

### 1. 核心映射机制

- `0`：代表该数字**不存在**
    
- `1`：代表该数字**存在**
    

### 2. 内存中的数字是怎么定位的？

计算机能操作的最小内存单位通常是**字节（Byte，1 Byte = 8 Bits）**。因此，底层的 BitMap 通常用一个 `byte` 数组（或 `int` 数组）来实现。

当我们要把一个数字 `N` 放入 BitMap 时，需要通过**位运算**进行三步定位：

1. **找到所在的字节（Byte Index）**：`Index = N / 8`（相当于向右移 3 位：`N >> 3`）
    
2. **找到在字节内的第几位（Bit Index）**：`Position = N % 8`（相当于与 7 模：`N & 7`）
    
3. **将该位置为 1**：将 `1` 左移 `Position` 位，然后与原字节进行**或（|）运算**。
    

> **举个例子：存入数字 `13`**
> 
> - `13 / 8 = 1`（在数组的第 1 个字节，即第二个字节，索引从0开始）
>     
> - `13 % 8 = 5`（在这个字节的第 5 位）
>     
> - 最终在内存里，就会把对应字节的第 5 位抹成 `1`。
>     

## 二、 BitMap 的适用场景

BitMap 的优势只有在**数据量极大（千万级、亿级）**且**数据范围相对紧凑**时才能发挥到极致。

### 1. 海量数据的去重与查重

- **典型业务**：
    
    - 电厂系统中，海量物联网历史报警事件 ID 的去重。
        
    - 视频网站（如B站、抖音）判定 1 亿个用户今天是否重复点击了某条视频。
        
- **为什么高效**：
    
    不需要把几亿个对象全部加载到内存里通过 `Set` 或 `Map` 去重。1 亿个用户 ID 只需要 1 亿个 Bit $\approx$ **12 MB 内存**，一张图片的大小就能完成亿级数据去重。
    

### 2. 用户画像筛选与精确人群圈选（标签系统）

这是互联网大厂（如电商、广告系统）最常用的高级玩法。

- **典型业务**：
    
    - 运营想要筛选出：_“性别为女（标签A）”_ **且** _“年龄在20-30岁（标签B）”_ **且** _“昨天有活跃（标签C）”_ 的用户去发优惠券。
        
- **为什么高效**：
    
    系统会为每个标签建立一个独立的 BitMap，下标代表用户全局 ID（UID）。
    
    - 标签A (女)：`[1, 0, 1, 1, 0]`
        
    - 标签B (25岁)：`[1, 1, 0, 1, 0]`
        
        筛选符合多条件人群时，不需要写复杂的 SQL `JOIN`，直接在内存里对两个 BitMap 进行**位与运算（AND）**：
        
        `[1, 0, 1, 1, 0] & [1, 1, 0, 1, 0] = [1, 0, 0, 1, 0]`（瞬间筛选出 UID 为 0 和 3 的用户）。CPU 进行位运算的速度是纳秒级的。
        

### 3. 快速排序（非负整数）

- **典型业务**：
    
    - 对 10 亿个不重复的无序手机号进行升序排序。
        
- **为什么高效**：
    
    将这 10 亿个数字依次倒入 BitMap 中（对应位置 1）。倒完之后，从 0 开始遍历这个 BitMap，只要看到该位是 `1`，就打印出对应的下标数字。遍历结束，排序自现。
    
    **时间复杂度为 $O(N)$**，比任何传统的快速排序、归并排序（$O(N \log N)$）都要快，且不需要额外的排序内存。
    

### 4. 布隆过滤器（Bloom Filter）的底层基石

- **典型业务**：
    
    - 你的背单词 App 导入模块预热，拦截不存在的词汇查询，防止缓存击穿。
        
- **为什么高效**：
    
    当数据是**字符串**（如单词、URL、邮箱）时，BitMap 无法直接映射下标。布隆过滤器通过引入多个 Hash 函数把字符串转成数字再勾选 BitMap，继承了 BitMap 超省内存的特点。
    

## 三、 BitMap 的局限性（面试必考陷阱）

BitMap 虽好，但绝不是银弹，它有两个**致命硬伤**：

1. **强依赖数据范围，稀疏数据会导致“内存爆炸”**
    
    - **惨案现场**：如果你只想存两个用户 ID：`1` 和 `2,018,244,377`（雪花 ID）。
        
    - **结果**：为了存这两个数，BitMap 必须向系统申请容纳 20 亿个格子的连续内存空间（约 **240 MB**）。原本 16 字节就能存下的数据，被爆涨了几千万倍。
        
2. **无法存储重复数据与权重**
    
    - **惨案现场**：一个格子只能表示 `0`（不存在）或 `1`（存在）。
        
    - **结果**：如果单词 `'apple'` 被用户背了 3 次，BitMap 没办法记录“3”这个频次，它只能记录“存在过”；同时它也无法附带任何额外信息（比如无法顺便存储这个单词的 AI 释义）。
        

## 四、 总结与技术选型

- **存的是紧凑的小整数，追求 100% 精准** $\rightarrow$ **直接用 BitMap**。
    
- **存的是稀疏的大整数（如雪花 ID、手机号）** $\rightarrow$ **升级使用 Roaring Bitmap（压缩位图）**。
    
- **存的是非整数（如单词、文本、图片 URL）** $\rightarrow$ **升级使用 布隆过滤器**。
